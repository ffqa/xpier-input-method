# 全部设置清单（Xpier 输入法）

> 本文件由 `tools/gen_settings_doc.py` 从随包配置自动生成，不是手写；
> 数据来源 `dist/Xpier.app/Contents/SharedSupport/` 下的
> `squirrel.yaml`（外观）、`wubi86_jidian.schema.yaml`（方案）、`default.yaml`（通用）。

## 怎么打开

点菜单栏输入法图标 → **Xpier 设置…** —— 打开的就是完整设置，下面每组一个标签页。
标签页标题不带条目数，干净。

窗口标题与状态栏会显示「构建 MM-dd HH:mm」：换包后如果这个时间没变，
说明输入法进程还是旧的，执行 `killall -9 Xpier` 再切一次输入法即可。

改完点「保存并部署」。**只写入改动过的项**，没动过的不会进 custom.yaml。

## 三层配置的关系

| 层 | 文件 | 作用 | 改后写到 |
| --- | --- | --- | --- |
| 外观 / 常规 | `squirrel.yaml` | 候选窗外观、状态图标、各 App 行为 | `~/Library/Xpier/squirrel.custom.yaml` |
| 方案 | `wubi86_jidian.schema.yaml` | 五笔码表、翻译器、简繁 | `~/Library/Xpier/wubi86_jidian.custom.yaml` |
| 通用 | `default.yaml` | Shift / Caps 行为、翻页键、方案选单 | `~/Library/Xpier/default.custom.yaml` |

`.custom.yaml` 优先级最高；重新安装输入法不会丢失，也不会改动内置默认值。

主题不是靠 `style/color_scheme` 选名字就完事：每个主题要写全下面这些键才不会有看不见的字。
**最容易踩的坑**：只写 `hilited_text_color` 而漏掉 `hilited_back_color`，
编码选中段就会变成「白字压在极浅背景上」——完全看不见。

| 配色键 | 作用 |
| --- | --- |
| `text_color` | 候选窗里未选中段的编码文字 |
| `hilited_text_color` | 候选窗里选中段的编码文字 |
| `hilited_back_color` | 上面这段编码的背景（不写 = 没有背景，极易看不见） |
| `candidate_text_color` | 未选中候选的文字 |
| `candidate_back_color` | 未选中候选的背景（一般留空） |
| `hilited_candidate_text_color` | 选中候选的文字 |
| `hilited_candidate_back_color` | 选中候选的背景 |
| `comment_text_color` | 候选注释文字 |
| `hilited_comment_text_color` | 选中候选的注释文字 |
| `label_color` / `hilited_candidate_label_color` | 候选序号（不写则按前景/背景自动混色） |
| `border_color` | 候选窗描边 |

> 注意：**内联显示编码**（`style/inline_preedit: true`）时，编码由客户端 App 自己画，
> 用的是 App 自身文字色 + 下划线，上面这些颜色一律不参与，也无法由主题控制。
> 但 Terminal / iTerm2 / MacVim / Emacs 在 `app_options` 里带 `no_inline: true`，
> 会被强制改成「编码显示在候选窗里」，此时这里的配色就直接决定看不看得清。
