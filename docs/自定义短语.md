## 1. 用户怎么用（定稿形态）

1. 在 `~/Library/Xpier/` 下建 `wubi_custom_phrase.dict.yaml`，
   一行一条（字和码之间是 **Tab**，不是空格）：
   ```yaml
   ---
   name: wubi_custom_phrase
   version: "1"
   sort: by_weight
   columns:
     - text
     - code
     - weight
   ...
   北京市海淀区xx号	addr	10000
   qingg@example.com aaa@bbb.com	mail	10000
   2026-09-17	date	10000
   ```
2. 切回输入法等半分钟（码表重编），直接敲码：
   `mail`→邮箱串、`date`→日期（全库唯一码，直接上屏）；
   `addr`→地址（与主码表“莽原”同码时，权重高者排第一）。
3. 多设备复用（下一步才做）：设置页填 gist 地址，保存时拉下来
   覆盖上面这个文件并触发部署。只读，不回传。

权重经验值：盖过主码表同码词用 `10000`（spike 实测 100 会输给“莽原”，
10000 反超第一）；不想盖过就写小或不写。

---

## 2. 原理（一句话）

Rime 原生的 `import_tables` 合并 —— 主词库
`wubi86_jidian.dict.yaml` 的 `import_tables` 加一行
`wubi_custom_phrase`，部署时（deploy）把用户文件编译进同一张
`wubi86_jidian.table.bin`。**不是**独立 translator，不走 affix，
和𡋤进 `wubi86_jidian_user.dict.yaml` 是同一条路。

## 3. spike 证据（rime_probe，2026-09-17）

| 输入 | 现象 | 说明 |
| --- | --- | --- |
| `mail` | 直接上屏 `qingg@example.com aaa@bbb.com` | 全库唯一码，auto_select 吃掉 |
| `date` | 直接上屏 `2026-09-17` | 同上 |
| `addr`（权重 100） | 候选 1.莽原 2.地址 | 输给主码表（主表 `莽原 addr 10`，但主表量级大） |
| `addr`（权重 10000） | 候选 1.地址 2.莽原 | 反超，可控 |
| `mai` | 候选含邮箱串第二 | 前缀联想里也混排 |
| `tffu` | 1.等 2.徒增（全程不变） | 主流程无回归 |
| 桩被用户文件遮掉 | `stubx` 有桩无用户文件时能上屏；有用户文件时 `stubx` 零候选 | ResourceResolver 用户优先，遮蔽干净 |

## 4. 两个关键决定

1. **随包必须带桩表**。`import_tables` 引用的表若两边都没有，
   部署只打一条 warning，主表照编（tffu 照打）—— 静默缺功能，
   用户会以为词库坏了。所以随包带一个只有 `stubx` 占位词条的桩，
   用户文件按 Rime 遮蔽规则覆盖它（上表最后一行已验证遮蔽干净）。
   进包时两处改：`data/plum/wubi86_jidian.dict.yaml` 加 import 行 +
   `data/plum/wubi_custom_phrase.dict.yaml` 桩文件。
2. **不要 `/` 前缀触发**（已证伪）。曾试 `affix_segmentor@custom_phrase`
   剥 `/` + `table_translator@custom_phrase` 查独立表：
   `/` 会被 punct_segmentor 独占切走（affix 排它后面就见不到 `/`），
   且 deploy 只给主 translator 编表，独立 translator 的表编不出来。
   清歌截图里也是裸码触发，裸码够了。
